# 三种生图方式

本 Skill 支持三种可选生图方式。三者只改变“由谁生成和如何保存”，不改变分镜、画风锁定、角色连续性、文件命名和质检标准。

## 模式选择

在进入生图阶段时，把选择写入单期 `00_项目配置.json`：

```json
{
  "image_generation": {
    "mode": "codex_imagegen",
    "prompt_source": "03_分镜表.md"
  }
}
```

`mode` 只能是：

- `codex_imagegen`：原有内置生图方式。适合 Codex 可以直接调用生图工具、用户要求无人值守连续制作的情况。
- `chatgpt_f12`：ChatGPT 网页端 F12 批量生图方式。适合用户希望使用自己的 ChatGPT 账号生图，并让浏览器把图片直接写入单期文件夹的情况。该模式只支持 `chatgpt.com`，需要用户在网页控制台手动粘贴并启动脚本，不能宣称完全无人值守。
- `gemini_f12`：Gemini 网页端 F12 批量生图方式。适合 ChatGPT 生图额度不足或用户明确选择 Gemini 的情况。该模式只支持 `gemini.google.com`，同样由浏览器把图片直接写入单期文件夹。

用户明确指定时遵从指定。用户未指定、多种方式都可用且正停留在生图阶段时，只询问一次；用户已经要求无人值守直出且没有等待选择时，默认沿用 `codex_imagegen`。ChatGPT 达到额度限制时，可以切换 `gemini_f12` 继续缺失镜头，但必须重新从目标文件夹扫描已有编号和哈希，不覆盖 ChatGPT 已完成的正确图片。

## 共同提示词来源

三种模式都必须先完成并校验本期 `03_分镜表.md`，然后逐镜动态编译提示词。不得复用上一期的标题、人物表、镜头数组或返工编号。

每个镜头的提示词由固定生成器组合，执行者 不直接拼接最终英文长提示词。至少包含：

1. `00_项目配置.json` 的本期 `title` 和风格锁定；
2. `03_分镜表.md` 的 B 节角色/物件连续性；
3. E 节当前正向画风锚点和统一禁止项；
4. 当前镜头的叙事任务、旁白语境、时间、人物、地点、动作、情绪、核心物件、构图和连续性禁止项；
5. `I10` 专用的“人物在左、右侧标题安全区、禁止文字”约束。
6. `scripts/image_prompt_compiler.py` 自动附加的镜头语言：机位与镜头感、主体侧、构图几何、前中后景、两项辅助叙事细节、相邻镜头差异和禁止空泛肖像。

如果分镜中的人物、地点、动作、情绪或禁止项仍是占位符，禁止开始任一模式的批量生图。镜头事实必须逐项来自本期分镜；统一编译器只负责表现方式，不得猜测或改变人物关系、地点和事件。

### 图片查看与返工

人物、地点、动作和构图按分镜生成；画风由项目配置统一提供，生成器不自行轮换机位。保存后按 visuals.md 查看一次，只有明确大错才按 quality-review.md 返工一轮；候选仍差就停止，不继续更新指令循环生图。具体命令集中在 commands.md。

## `codex_imagegen` 模式

按 `references/visuals.md` 的既有流程调用内置生图能力。每张图生成后立即写入分镜指定路径并记录结果；失败时只重试当前待完成镜头。生成完成后仍需逐张查看和运行唯一性校验。

## `chatgpt_f12` 模式

先从 Skill 根目录运行：

具体命令见 [commands.md](commands.md)。

生成的单期脚本固定为：

```text
<单期项目目录>/ChatGPT_F12_批量生图.js
```

该脚本会从本期配置和分镜注入标题、角色、画风、禁止项和全部镜头；Skill 内的通用模板不得包含任何一期的具体主题或镜头。

### 固定模板约束

`assets/chatgpt-f12-batch-template.js` 是 ChatGPT 网页端固定运行模板，版本号只在锁文件中维护。`assets/chatgpt-f12-template-lock.json` 保存权威版本和 SHA-256，`build_chatgpt_f12_script.py` 内也固化相同版本与哈希；三者任一不一致时必须拒绝生成。生成单期脚本时只允许替换唯一的 `/*__PROJECT_CONFIG__*/` 数据占位符；不得根据主题复制、拼接或临时改写 DOM 选择器、等待逻辑、保存逻辑、重试策略和界面代码。模板发生真实网页兼容问题时，只有用户明确要求升级或修复GPT模板，才允许集中修改模板、提升版本、更新两处锁定哈希并通过语法与生成器回归检查；禁止只修某一期生成产物。

用户在最新版 Chrome 或 Edge 中打开 `chatgpt.com` 生图对话，按 F12 进入 Console，粘贴单期脚本并回车，然后选择单期项目根目录。脚本自动把 `H/I` 镜头写入 `画面/开头/`，把 `S` 镜头写入 `画面/正文/`。

脚本必须保持以下安全行为：

- 默认只生成目标目录中缺失的编号，不覆盖已有正确图片；
- 只以 ChatGPT 精确的停止生成按钮、本次新增助手回复和该回复中的新图片元素判断状态；禁止用全局进度条、模糊“加载中”元素或 Gemini 状态文案判断；
- ChatGPT 图片已经显示但精确停止按钮持续存在时，不得无限等待：先从最后一条用户提示识别镜头编号并把当前可见图片成功保存或判定为需重做；只有图片已经落盘或明确无效后，才允许脚本自动点击停止按钮释放输入框并继续下一镜；
- 如果点击停止后输入框仍锁定，说明当前对话运行状态已经损坏。ChatGPT模板在用户首次点击开始时必须预先打开一个同源工作窗口，控制逻辑和文件夹句柄保留在原页面；确认当前图片已保存后，必须在工作窗口中触发真正的“新聊天/新对话”，并硬检地址已离开旧 `/c/<对话ID>`、新输入框可用且停止按钮消失，才能继续缺失镜头。普通刷新旧对话不属于恢复方案。不得刷新承载控制脚本的原页面，否则控制状态和文件夹权限会丢失；浏览器首次阻止弹窗时允许请求用户仅完成一次弹窗授权。
- 明确结束但没有图片、抓到隐藏旧图、原图提取失败或内容哈希完全重复时，自动强化“换构图、换机位、不得复用旧图”的提示并重做当前镜头；
- 只把本次新增且稳定的图片绑定到当前编号，禁止拿上一张旧图冒充；
- 保存前转换为真实 PNG，并检查内容哈希；单镜每轮最多自动尝试 6 次，连续失败时移到队尾，最多执行 3 轮，期间继续完成其他镜头，不要求用户手动续跑；
- 选择了目标文件夹后，写入失败先在内部自动重试，禁止偷偷降级到浏览器默认下载目录；浏览器撤销文件夹权限等无法自行恢复的情况才允许停止并明确报告。

## `gemini_f12` 模式

从 Skill 根目录运行：

具体命令见 [commands.md](commands.md)。

生成的单期脚本固定为：

```text
<单期项目目录>/Gemini_F12_批量生图.js
```

`assets/gemini-f12-batch-template.js` 是独立的 Gemini 网页端固定运行模板，只允许生成器替换 `/*__PROJECT_CONFIG__*/` 数据占位符。它不得引用 ChatGPT 的输入框、停止按钮、回复节点或图片节点，也不得和 ChatGPT 模板合并成“自动识别平台”的混合脚本。Gemini 的深色与浅色主题共用同一发送逻辑，禁止按按钮颜色或 SVG 图标路径定位；模板先使用语义选择器，再在当前输入组件右下角做几何定位，最后用输入框 Enter 事件兜底。任何触发后都必须确认输入框清空、出现新用户查询或进入生成状态，不能把一次 `.click()` 当作发送成功。

用户在最新版 Chrome 或 Edge 中打开 `gemini.google.com` 的生图对话，进入 Console 粘贴脚本并选择同一个单期项目根目录。脚本先扫描 `画面/开头/` 与 `画面/正文/`，只补缺失编号，因此可以在 ChatGPT 达到额度限制后接续生产；平台切换不改变镜头编号、目标路径和提示词来源。

Gemini 模板应只使用 Gemini 自身的输入框、精确停止按钮、用户查询节点、模型回复节点和回复内可见图片判断状态。发送按钮的 aria-label 或类名变化时，固定模板必须通过当前输入组件内的范围受限兜底继续定位，不得让 执行者 手改某一期脚本。自动重试、重复哈希处理、延后失败镜头、PNG 转换、文件夹直写和不覆盖已有图片的规则与 ChatGPT 模板一致，但两个模板分别维护和测试。

## 共同验收

无论采用哪种方式，完成后都必须：

1. 核对期望编号、实际文件、缺失项和额外项；
2. 计算 SHA-256，确认每个镜头内容哈希唯一；
3. 每张原图保存后看一次，检查画风、人物、明显畸形和剧情大错；
4. 重点检查相邻镜头的近似重复、角色/地点串场和模型把上一提示词延续到下一编号的问题；
5. 候选确认明显改善后才替换；明确大错未解决时报告，不进入最终交付。

“文件数量齐全”和“哈希不同”都不能替代内容审查。画面内容与分镜错位时，状态仍是待返工。
