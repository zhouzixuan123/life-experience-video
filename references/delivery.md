# 成片确认与交付

## 输出

默认最终成片目录只有 [主题].mp4、封面_4x3.jpg（1600×1200）、封面_3x4.jpg（1200×1600）、封面_16x9.jpg（1920×1080）。字幕、封面底图、缩略图和工作记录放在 work，只有用户索要时额外交付。剪映草稿按专项文件导出。

三张封面分别生成匹配比例的底图，再从项目完整标题排版；中心留白与人物完整构图按 [covers.md](covers.md) 执行。明显标题缺字、文字遮挡人物、人物被裁掉才局部修复，不因审美偏好反复生成。

## 简短成片确认

validate_final_delivery.py --prepare 自动绑定当前视频，生成 final_av_review.json。实际查看开头的冷开场、九宫格、主题定格后填写 opening_complete；查看正文入口、中后段、结尾及修改点后填写 body_ok；查看三张封面后填写 covers_ok。

能听时用 audio_mode=listening 并确认 sound_ok；不能听时 machine_only，保留说明。major_errors 只记录确定的大错；无大错不填长篇评分。脚本只验证记录，不代替实际观看。

运行 publish_preview.py --label final，一次检查真实帧数、时长、解码、声音存在、当前配音和图片结果及这份查看记录，再发布成片。它不额外渲染对照视频，也不跑审美评分。

## 清理

保留配置、文稿、源配音、当前处理音、采用图片、ASR、recipe、音频计划与最终文件。失败大文件、临时截图、可重建 stems 和项目内缓存在完成后清理；每类回退产物最多一个。正在查看/占用的文件先关闭占用或写 pending，避免覆盖失败。

日常不反复保存时间戳全片。维护 Skill 的历史只通过 Git 回溯，不放入分发文档。
